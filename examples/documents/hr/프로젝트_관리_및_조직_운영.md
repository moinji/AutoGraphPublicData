## 제1장 총칙

### 제1조 (목적)
본 매뉴얼은 당사의 프로젝트 수행 및 조직 운영에 관한 표준 절차와 기준을 규정하여, 효율적인 자원 배분과 체계적인 프로젝트 관리를 실현함을 목적으로 한다.

### 제2조 (적용 범위)
본 매뉴얼은 당사에서 수행하는 모든 프로젝트(예산 1,000만 원 이상)에 적용한다. 예산 1,000만 원 미만의 소규모 작업은 팀 내부 운영 기준에 따른다.

당사의 프로젝트 거버넌스 구조는 다음과 같다.

#### 프로젝트 1: GraphRAG SaaS 개발

| 항목 | 내용 |
|------|------|
| 프로젝트명 | GraphRAG SaaS 개발 |
| 상태 | Active (진행 중) |
| 예산 | 5억 원 |
| 기간 | 2025년 7월 ~ 2026년 12월 (18개월) |
| 담당 팀 | 개발1팀 (기술본부, 서울 본사 8층) |
| 프로젝트 매니저 | 정개발 팀장 (연봉 9,500만 원) |
| 기술 리드 | 한개발 시니어 (연봉 7,800만 원) |
| 스폰서 | 김대표 대표이사 (연봉 1억 5,000만 원) |

**프로젝트 개요**
GraphRAG SaaS는 그래프 기반 RAG(Retrieval-Augmented Generation) 기술을 SaaS 형태로 제공하는 당사의 핵심 제품이다. 김대표 대표이사가 직접 스폰서로 참여하여 전사적 지원을 받고 있으며, 당사의 기술 경쟁력을 결정짓는 전략적 프로젝트이다.

**팀 구성 및 역할**

| 이름 | 직급 | 역할 | 핵심 스킬 |
|------|------|------|----------|
| 정개발 | 팀장 | PM, 백엔드 아키텍처 | Python, AWS, 프로젝트 관리 |
| 한개발 | 시니어 | 기술 리드, 코어 엔진 개발 | Python, 데이터 분석, AWS |
| 윤개발 | 주니어 (2023년 입사) | 백엔드 개발, API 구현 | Python, React |

**마일스톤**

| 단계 | 기간 | 주요 산출물 | 예산 배분 | 상태 |
|------|------|----------|:--------:|:----:|
| Phase 1: 코어 엔진 | 2025.07 ~ 2025.12 | 그래프 구축/쿼리 엔진 | 1.5억 원 | 완료 |
| Phase 2: API/인프라 | 2026.01 ~ 2026.04 | REST API, 클라우드 인프라 | 1.5억 원 | 진행 중 |
| Phase 3: SaaS 플랫폼 | 2026.05 ~ 2026.08 | 멀티테넌트, 과금 시스템 | 1.2억 원 | 예정 |
| Phase 4: 런칭/안정화 | 2026.09 ~ 2026.12 | 베타 런칭, 성능 최적화 | 0.8억 원 | 예정 |

**기술 스택**: Python (FastAPI), Neo4j, PostgreSQL (pgvector), React, AWS (EKS, S3, RDS)

**리스크 관리**
- 리스크 1: 핵심 개발 인력 부족 → 대응: 2026년 상반기 시니어 1명 추가 채용 (인사팀 박인사 팀장 진행 중)
- 리스크 2: AWS 비용 초과 → 대응: 월별 비용 모니터링 및 Reserved Instance 활용
- 리스크 3: 기술 난이도 → 대응: 한개발 시니어 AWS Solutions Architect 자격 취득 추진

#### 프로젝트 3: CI/CD 파이프라인 구축

**성과 요약**

| 지표 | 도입 전 | 도입 후 | 개선률 |
|------|-------:|-------:|:-----:|
| 빌드 시간 | 45분 | 12분 | 73% 단축 |
| 배포 빈도 | 주 1회 | 일 2회 | 10배 증가 |
| 장애 복구 시간 | 4시간 | 30분 | 87% 단축 |
| 테스트 커버리지 | 45% | 82% | 37%p 향상 |

**구축 인프라**: GitHub Actions, Docker, AWS ECS, SonarQube, Selenium, Jest

**프로젝트 완료 평가**: 송QA 팀장은 본 프로젝트 완료 평가에서 S등급을 받았으며, 이는 반기 정기 평가의 프로젝트 완료 평가(20%) 항목에 반영되었다.

## 제3장 프로젝트 수행 방법론

### 제5조 (애자일 방법론 적용)

당사는 소프트웨어 개발 프로젝트에 애자일(Agile) 방법론을 표준으로 적용한다. 전 팀장급은 애자일 프로젝트 관리 교육(16시간)을 필수 이수해야 한다.

#### 5.1 스크럼 프레임워크

| 의식 (Ceremony) | 주기 | 참석자 | 소요 시간 |
|----------------|------|--------|:--------:|
| 스프린트 계획 | 2주마다 | PM, 기술 리드, 팀원 전원 | 2시간 |
| 데일리 스탠드업 | 매일 (09:30) | 팀원 전원 | 15분 |
| 스프린트 리뷰 | 2주마다 | PM, 팀원, 이해관계자 | 1시간 |
| 스프린트 회고 | 2주마다 | PM, 팀원 | 1시간 |
| 백로그 정제 | 주 1회 | PM, 기술 리드 | 1시간 |

#### 5.2 프로젝트별 스프린트 운영 현황

- **GraphRAG SaaS 개발**: 2주 스프린트, 정개발 팀장이 스크럼 마스터 겸임. 한개발 시니어가 기술 리뷰, 윤개발 주니어가 백엔드 스토리 담당.
- **모바일 앱 리뉴얼**: 2주 스프린트, 서개발 시니어가 기술 리드로서 아키텍처 의사결정 주도.
- **해외 시장 진출**: 4주 스프린트 (영업 특성 반영), 오해외 팀장이 스프린트 계획 주관.

| 이슈 보고 | 수시 | 발생 팀 | 본부장, PMO | 긴급 이슈 발생 시 즉시 보고 |
| 마일스톤 보고 | 마일스톤 완료 시 | PM | 스폰서, 본부장 | 산출물, 품질 지표, 다음 단계 계획 |

정개발 팀장은 GraphRAG SaaS 주간 보고를 최기술 본부장에게, 최기술 본부장은 기술본부 월간 보고를 김대표 대표이사에게 제출한다.

## 제4장 자원 관리

### 제7조 (인력 배치 원칙)

1. **전담 배치**: 핵심 프로젝트(예산 3억 원 이상)에는 전담 인력을 우선 배치한다.
2. **겸임 제한**: 1인당 최대 2개 프로젝트까지 겸임 가능 (주 프로젝트 70% + 부 프로젝트 30%).
3. **스킬 매칭**: 프로젝트에 필요한 스킬(Python, Java, React, AWS, 프로젝트 관리, 데이터 분석, 영어 비즈니스, 리더십)과 보유 스킬을 매칭하여 최적 인력을 배치한다.
4. **인력 요청**: PM이 인사팀 박인사 팀장에게 인력 요청서를 제출하고, 최기술 본부장(기술본부) 또는 해당 본부장의 승인을 받아 배치한다.

### 제8조 (현재 인력 배치 현황)

| 프로젝트 | 인원 | 핵심 인력 | 충원 필요 |
|----------|:----:|----------|:--------:|
| GraphRAG SaaS 개발 | 3명 | 정개발(PM), 한개발(TL), 윤개발 | 시니어 1명 |
| 모바일 앱 리뉴얼 | 1명 (+충원 예정 2명) | 서개발(TL) | 주니어 2명 |
| CI/CD 파이프라인 구축 | - | 송QA(PM) - 완료 후 유지보수 | - |
| 해외 시장 진출 | 2명 | 오해외(PM) | 대리 1명 |
| ERP 시스템 도입 | 기획 단계 | 이재무(PM) | 본격 착수 시 결정 |

### 제9조 (크로스 팀 협업)

당사는 프로젝트 간 시너지를 위해 크로스 팀 협업을 장려한다.

| 협업 유형 | 관련 팀 | 내용 |
|----------|--------|------|
| 기술 자문 | 개발1팀 → 개발2팀 | 한개발 시니어가 서개발 시니어에게 Python 백엔드 아키텍처 자문 |
| 품질 검증 | QA팀 → 개발1팀, 개발2팀 | 송QA 팀장이 CI/CD 기반 자동화 테스트 지원 |
| 제품 현지화 | 개발1팀 ↔ 해외영업팀 | GraphRAG SaaS 다국어 지원을 위한 공동 작업 |
| 영업 연계 | 국내영업팀 ↔ 해외영업팀 | 임영업 팀장의 B2B 영업 노하우를 오해외 팀장에게 공유 |
| 시스템 연동 | 재무팀 ↔ 기술본부 | ERP 도입 시 기존 시스템과의 연동 방안 기술 검토 |

## 제5장 프로젝트 생명주기

### 제10조 (프로젝트 단계별 절차)

#### 단계 1: 착수 (Initiation)
1. 프로젝트 제안서 작성 (PM 후보자)
2. 사업 타당성 검토 (재무팀 이재무 팀장)
3. 프로젝트 승인 (김대표 대표이사, 예산 1억 원 이상)
4. PM 임명 및 팀 구성 (인사팀 박인사 팀장 협의)
5. 킥오프 미팅 개최

#### 단계 2: 계획 (Planning)
1. WBS(Work Breakdown Structure) 작성
2. 일정 수립 (간트 차트)
3. 예산 계획 수립 (재무팀 승인)
4. 리스크 식별 및 대응 계획
5. 의사소통 계획 수립

#### 단계 3: 실행 (Execution)
1. 스프린트 단위 업무 수행 (애자일 프로젝트의 경우)
2. 정기 보고 (주간/월간)
3. 이해관계자 커뮤니케이션
4. 변경 요청 관리

#### 단계 4: 통제 (Monitoring & Control)
1. 진행률 추적 (번다운 차트, EVM)
2. 품질 관리 (코드 리뷰, 테스트)
3. 리스크 모니터링
4. 예산 집행 모니터링 (재무팀 월간 정산)

#### 단계 5: 종료 (Closing)
1. 최종 산출물 인수인계
2. 프로젝트 완료 보고서 작성
3. 교훈 (Lessons Learned) 회의
4. 프로젝트 완료 평가 (성과 평가 반영)
5. 자원 해제 (인사팀 통보)
